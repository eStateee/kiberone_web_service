# Напоминание о дне рождения ребёнка

Реализация тестового задания. Фича состоит из двух частей: автоматической
рассылки напоминаний за 7 дней и просмотра ближайших дней рождения в боте.

Код разделён по двум репозиториям:

- бэкенд — этот репозиторий, ветка `dev`;
- бот — `kiberone_telegram_bot`, ветка `dev`.

---

## 1. Что сделано

### Модель `BirthdayMessageStatus` (`app_kiberclub/models.py`)

Хранит факт отправки напоминания. Уникальность пары «ребёнок + год»
обеспечена ограничением на уровне базы:

```python
constraints = [UniqueConstraint(fields=("client", "year_of_future_birthday_message"), ...)]
```

В поле пишется **год предстоящего дня рождения**, а не год отправки. Это
принципиально: у ребёнка, родившегося 3 января, напоминание уходит
28 декабря — то есть в предыдущем календарном году. Если хранить год
отправки, то 2 января условие «уже отправляли в этом году» перестанет
выполняться и родитель получит второе сообщение.

Ограничение уникальности здесь не подстраховка, а условие корректной
работы `get_or_create`: между его `SELECT` и `INSERT` есть промежуток,
и при одновременном запуске двух задач от дублей спасает именно индекс.

### Выборка (`app_api/utils/util_birthday.py`)

`get_children_w_coming_birthday(window_days, telegram_id, is_exact_match, is_client_obj_need)`

Для каждого ребёнка вычисляется дата ближайшего дня рождения: день и месяц
из `dob`, год — текущий, а если праздник уже прошёл, то следующий. Из этой
одной даты считаются все остальные величины: сколько дней осталось, сколько
лет исполнится и какой год записать в отметку. Они согласованы между собой
по построению и не могут разойтись.

Отдельно обрабатывается 29 февраля: `date.replace` на невисокосном годе
выбрасывает `ValueError`, такие дети пропускаются.

Два режима: окно (`days_until <= window_days`) для эндпоинта и точное
совпадение (`days_until == window_days`) для задачи.

### Эндпоинт (`app_api/views.py`, `app_api/urls.py`)

```
GET /api/upcoming_birthdays/?telegram_id=<id>&window_days=30
```

```json
{"success": true, "data": [{"client_id": 1682, "name": "Чепик Валерия Витальевна",
  "dob": "2014-09-08", "upcoming_age": 12, "days_until": 7, "balance": "150.00"}]}
```

Баланс берётся из AlfaCRM запросом `find_client_by_id`. Если CRM недоступна,
в ответ уходит `"balance": null` — эндпоинт не падает. Без `telegram_id`
возвращается `400`, а не `500`: это ошибка запроса, а не сервера.

Служебные поля выборки (`crm_id`, `branch_id`, `telegram_id`,
`next_birthday_year`) наружу не отдаются.

### Celery-задача (`app_api/tasks/birthday_tg_message.py`)

`send_birthday_tg_message` — раз в день находит детей, у которых день
рождения ровно через 7 дней, и отправляет родителю сообщение.

Порядок действий выбран так, чтобы не потерять напоминание и не отправить
его дважды:

1. `get_or_create` создаёт отметку и сообщает, была ли она уже;
2. сообщение уходит только при `created is True`;
3. если отправка не удалась, отметка удаляется — завтра задача попробует снова.

Для третьего пункта понадобилась функция, которая возвращает результат:
существующая `send_telegram_message` глотает исключения внутри себя и всегда
возвращает `None`. Менять её было нельзя — ею пользуются четыре другие
задачи, — поэтому рядом добавлена `send_telegram_message_with_result`.

Модуль зарегистрирован в `app_api/tasks/__init__.py`: Celery находит задачи
через импорт пакета `tasks`, и без этой строки задача не появилась бы
в списке worker'а.

### Склонение имени (`app_api/utils/util_name_case.py`)

`to_genitive` ставит имя в родительный падеж, чтобы фраза читалась как
«у Валерии День Рождения», а не «у Валерия». Учтены чередование `ы`/`и`
после шипящих и заднеязычных (Ольги), женские имена на мягкий знак
(Любови), беглые гласные (Петра, Павла, Льва), несклоняемые имена и
латиница. Незнакомое имя возвращается без изменений.

`get_first_name` достаёт имя из ФИО: в CRM данные хранятся как
«Фамилия Имя Отчество», поэтому имя — второе слово.

### Бот (репозиторий `kiberone_telegram_bot`)

- кнопка «🎂 Дни рождения» — только в `get_client_keyboard`, то есть у статуса «2»;
- `get_upcoming_birthdays` в `service/api_requests.py` — передаёт параметры
  **строкой запроса** (`params=`), а не телом, как соседние функции;
- обработчик `handlers/inline_handlers/upcoming_birthdays.py` — список детей,
  сообщение о пустом списке, кнопка возврата в главное меню;
- роутер зарегистрирован в `bot.py`.

Обработчик различает две ситуации: `None` от API означает сбой запроса,
пустой список — что дней рождения действительно нет. Сообщения разные.

## 2. Как проверить

### Тесты

23 теста, внешние сервисы подменены заглушками — ни CRM, ни Telegram
не нужны:

```bash
cd kiberone_web_service && .\.venv\Scripts\python.exe manage.py test app_api
```

Покрыты: склонение имён, выборка (включая переход через Новый год,
29 февраля, отсутствие даты рождения, фильтр по родителю), эндпоинт
(400 без параметра, пустой список, недоступная CRM, отсутствие служебных
полей) и задача (отправка, защита от повтора, откат отметки при сбое).

### Тестовые данные

Команда переставляет дни рождения нескольким детям и запоминает исходное
состояние, чтобы потом всё вернуть:

```bash
cd kiberone_web_service && .\.venv\Scripts\python.exe manage.py birthday_testdata prepare --telegram-id ВАШ_TELEGRAM_ID
```

```bash
cd kiberone_web_service && .\.venv\Scripts\python.exe manage.py birthday_testdata restore
```

Параметры: `--count` (сколько детей, по умолчанию 3), `--days` (через
сколько дней день рождения, по умолчанию 7).

### API

```bash
curl "http://127.0.0.1:8000/api/upcoming_birthdays/?telegram_id=ВАШ_TELEGRAM_ID&window_days=30"
```

### Celery-задача

```bash
cd kiberone_web_service && .\.venv\Scripts\python.exe manage.py shell -c "from app_api.tasks.birthday_tg_message import send_birthday_tg_message; print(send_birthday_tg_message())"
```

Запустите дважды. Первый раз сообщение приходит и в админке появляется
запись в разделе «Поздравления с днем рождения», второй раз — ничего
не отправляется и новых записей не появляется.

Расписание задаётся в админке: «Периодические задачи» →
`app_api.tasks.birthday_tg_message.send_birthday_tg_message`, раз в сутки.

### Бот

1. Нажмите Start у тестового бота — Telegram не разрешает боту писать первым.
2. Отправьте `/menu` (не `/start`: он полезет синхронизировать данные с CRM).
3. Кнопка «🎂 Дни рождения» должна быть в меню, если статус пользователя «2».
4. Нажмите — придёт список ближайших дней рождения.

## 3. Ограничения

- **Баланс требует доступа к AlfaCRM.** С компьютера разработчика CRM
  отвечает только через VPN. Без него эндпоинт вернёт `"balance": null`,
  а в сообщении будет «для уточнения баланса обратитесь к менеджеру» —
  ни то, ни другое не ломает работу.
- **Дети с датой рождения 29 февраля пропускаются.** Решение осознанное
  и записано в комментарии; при желании заменяется на 28 февраля.
- **Напоминание одно — за 7 дней.** Если понадобится второе, скажем за 30,
  в ограничение уникальности нужно будет добавить третье измерение — вид
  напоминания, иначе одно напоминание заблокирует другое.
